# Hermes Device Worker Client

This folder is the worker client generated by the Hermes plugin command
`hermes device sync-dist`. Copy it from the central Hermes machine to each
trusted Mac you want Hermes to control.

## Quick Start

On the worker Mac:

```bash
scp -r <hermes-ssh-host>:~/.hermes/device-worker ~/device-worker
cd ~/device-worker
./install.sh --install-cua
./check_permissions.sh
./run.sh --display-name <node-name> --host 0.0.0.0 --port 18888
```

`<hermes-ssh-host>` can be an SSH alias such as `hermes`, or a full target such
as `allen@192.168.1.130`. If `scp` cannot resolve `hermes`, use `user@ip` or add
an SSH alias in `~/.ssh/config`.

The worker prints a token. Approve it on the central Hermes machine:

```bash
hermes device node approve <node-name> ws://<worker-lan-ip>:18888 <token>
hermes device node ping <node-name>
hermes device node capabilities <node-name>
```

If you do not know the worker LAN IP, run this on the Mac:

```bash
ipconfig getifaddr en0 || ipconfig getifaddr en1
```

Expected GUI-ready capability:

```text
"computer_use": true
```

Expected coding-ready capabilities:

```text
"workspace": true
"terminal_sessions": true
```

The central Hermes plugin exposes a compact tool surface:

- `device_node` for worker discovery/status
- `device_workspace` for files, repos, search, patches, and git status/diff
- `device_terminal` for persistent commands, tests, REPLs, and dev servers
- `device_desktop` for GUI capture/click/type/key/scroll

Terminal sessions are persistent until killed or until the worker stops. The
worker closes all sessions on SIGINT/SIGTERM, caps the number of sessions, keeps
terminal output in bounded buffers, and prunes exited sessions after a short
retention window.

## macOS GUI Control

Shell access works without GUI permissions. Desktop/app control requires:

- `cua-driver`
- Accessibility permission
- Screen Recording permission

The helper opens the right panes and triggers likely prompts:

```bash
./check_permissions.sh
```

macOS still requires manual approval. Grant permissions to the terminal or
launcher running the worker, and to Python or `cua-driver` if macOS shows them.
Restart the worker after changing permissions.

## Run As A Service

After the worker runs successfully in a terminal:

```bash
./install_launchd.sh <node-name>
launchctl kickstart -k gui/$UID/com.hermes.device-worker
```

Logs:

```bash
tail -f ~/Library/Logs/hermes-device-worker.log
tail -f ~/Library/Logs/hermes-device-worker.err.log
```
